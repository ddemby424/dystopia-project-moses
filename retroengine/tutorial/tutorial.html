Lesson 1 — Tour the project folders

Lesson 1 of 15 · 5 min

Time: about 5 minutes

Payoff: you can point at every important file and say what it does.

RetroEngine has two folders that matter. Think of them like a TI-89 program you edit, and the "compiled" copy you actually run.

  • Source (the folder you edit): the directory that contains app.js, dmbtech1.js, build.py, and assets/. In this workspace that is /workspace/dfide/re/. The standalone engine library also lives at /workspace/dfide/dmbtech1/ (published at /dystopia-project-moses/dmbtech1/).
  • Built copy (what you publish): running python3 build.py writes a playable site to the sibling folder ../retroengine/. The live site is that built copy, hosted at ddemby424.github.io/dystopia-project-moses/retroengine/.

index.html is the shell. Play mode is the standalone DMB Tech 1 library in dmbtech1.js (createEngine / createRuntime). app.js is the 2D editor plus room templates and starter levels; it imports dmbtech1.js. three.js r128 is a peer dependency, loaded from a pinned CDN import map, the way a TI-89 program might call built-in graph commands instead of drawing every pixel itself.

3D coordinates, in one breath

DMB Tech 1 stores the map as a 2D grid: x across, y depth. When it builds the 3D scene, map x becomes three.js x, map y becomes three.js z, and three.js y is up (height). One grid cell is 1 unit, about 2 meters. Eye height is the constant EYE (0.62) in dmbtech1.js, measured above the floor.

Lesson 4 — Load and scale a GLB in code

Lesson 4 of 15 · 10 min

Time: about 10 minutes

Payoff: you know the exact functions DMB Tech 1 uses, and you can point a slot at a new file.

A .glb is a 3D model in one file: the shape, the colors, and sometimes bones plus animations. DMB Tech 1 does not have a registerModel() function. It has slots. If a slot has a file, loadGlb fetches it, normalizeModel sizes it, and attachModel (or buildGunFromGlb for guns) swaps it in.

Compare

on a TI-89 this is like loading a picture variable and then scaling it so it fits a window. In VB, think LoadPicture plus setting Width and Top so the graphic sits on a floor line.

1. Put the file in the right folder

Copy your .glb into the source folder:

code
assets/models/my_soldier.glb

Keep the name simple: letters, numbers, underscores. After you run build.py, the same file must exist in ../retroengine/assets/models/ or the hosted site will 404.

2. How DMB Tech 1 actually loads a GLB

These are the real functions from dmbtech1.js. Comments were added for this tutorial. Do not paste this block back into dmbtech1.js as a second copy — it is already there.

javascript
// Cache: if two soldiers share one file, download it only once.
const glbCache = {};

// src is a path, a full URL, or a data: URL from an upload.
function loadGlb(src) {
  // No loader (or no path) → give back null, and the built-in mesh stays.
  if (!THREE.GLTFLoader || !src) return Promise.resolve(null);
  // First time we see this src, start a load and remember the Promise.
  if (!glbCache[src]) glbCache[src] = new Promise(res => {
    // Blender often embeds a sun light and a camera. If we kept them,
    // every enemy copy would add a bright light and blow the scene out.
    const strip = g => {
      const rm = [];
      g.scene.traverse(o => { if (o.isLight || o.isCamera) rm.push(o); });
      rm.forEach(o => o.parent && o.parent.remove(o));
      return g;
    };
    try {
      // GLTFLoader is three.js's reader for .glb / .gltf files.
      new THREE.GLTFLoader().load(
        src,
        g => res(strip(g)),               // success: strip lights, then keep it
        undefined,                        // no progress callback
        err => {                          // failure: warn, but do not crash
          console.warn('RetroEngine: model failed to load', String(src).slice(0, 80), err && err.message);
          res(null);
        }
      );
    } catch (e) { res(null); }
  });
  return glbCache[src];
}

3. How it is scaled and stood on the floor

normalizeModel uses a bounding box (Box3) — the smallest box that fits the mesh. It scales the model so its height matches the slot, centers it on X and Z, and lifts the lowest point to y = 0 (the floor). Hovering enemies pass centered = true so they sit around their mid-point instead.

javascript
function normalizeModel(scene, height, centered) {
  // holder is the object we add to the world; model is a clone of the file.
  const holder = new THREE.Group(), model = cloneSkinned(scene);
  holder.add(model);
  model.updateMatrixWorld(true);                 // bake current transforms
  const b = new THREE.Box3().setFromObject(model);
  if (b.isEmpty()) return null;                  // nothing to measure
  const size = b.getSize(new THREE.Vector3());
  const c = b.getCenter(new THREE.Vector3());
  // Scale so the model's height equals the slot height (spec.h or the enemy def).
  const s = height / Math.max(size.y, 1e-4);
  model.scale.multiplyScalar(s);
  // Center X/Z. If centered, also mid Y; otherwise sit the feet on y = 0.
  model.position.set(-c.x * s, centered ? -c.y * s : -b.min.y * s, -c.z * s);
  model.traverse(o => {
    if (o.isMesh) {
      o.frustumCulled = false;                   // never pop out at the screen edge
      if (o.material && o.material.map) o.material.map.encoding = THREE.sRGBEncoding;
    }
  });
  return holder;
}

Skinned (rigged) models must be cloned with THREE.SkeletonUtils.clone. A plain .clone() would make every soldier share one skeleton, so animating one would twitch all of them.

4. Point a built-in slot at your file

The built-in pack is the ASSET_PACK table in dmbtech1.js. Each key is a slot. h is the target height. tint darkens the colors. Guns use len (barrel length in world units), and sometimes flip or off.

javascript
const ASSET_PACK = {
  // Soldiers use this file and are scaled to height 1.12.
  enemy_grunt: { src: 'assets/models/soldier_swat.glb', h: 1.12, tint: 0.72 },
  enemy_drone: { src: 'assets/models/robot_flying_gun.glb', h: 0.46, tint: 0.7 },
  enemy_heavy: { src: 'assets/models/robot_legs_gun.glb', h: 1.3, tint: 0.62 },
  enemy_titan: { src: 'assets/models/robot_large_gun.glb', h: 1.45, tint: 0.55 },
  // Weapons 2–5 (shotgun, rifle, plasma, rocket). Index matches WEAPON_DEFS.
  weapon_2: { src: 'assets/models/gun_shotgun.glb', len: 0.66 },
  weapon_3: { src: 'assets/models/gun_rifle.glb', len: 0.64 },
  weapon_4: { src: 'assets/models/gun_scifi_rifle.glb', len: 0.58 },
  weapon_5: { src: 'assets/models/gun_rocket.glb', len: 0.5, flip: true, off: [0.06, -0.05, 0.02] }
};

The game builds the path as assetBase + p.src. When you open the app from a real web server, assetBase is usually '', so the path is just assets/models/my_soldier.glb next to index.html. If you open the page as file://, assetBase becomes HOSTED_BASE (the live GitHub Pages URL) so models can still load from the hosted copy.

5. Guns, and the default starting firearm

First-person guns that have an ASSET_PACK entry go through buildGunFromGlb: the longest axis is lined up with -Z (barrel away from the camera), then the gun is scaled to spec.len.

The default starting firearm is not a GLB. It is weapon index 1 (the second slot, after the wrench at index 0). WEAPON_DEFS[1] is the Pulse Cannon. Its id is still 'pistol' so existing maps and pickups stay compatible. There is no weapon_1 entry in ASSET_PACK, so the first-person mesh comes from buildWeaponMesh — a compact procedural model (amber coils, rusted shroud, cyan muzzle flash) scaled with inner.scale.setScalar(0.62). assets/models/gun_pistol.glb is still in the folder but is not loaded as the default.

javascript
// WEAPON_DEFS[1] — the gun you start with. id stays 'pistol' for map compatibility.
{ id: 'pistol',  name: 'Pulse Cannon',    ammo: null,    cd: 0.13, dmg: 28, pellets: 1, spread: 0.008, auto: true, proj: 'pulse', speed: 22, recoil: 0.14, snd: 'pulse' },

ammo: null means infinite ammo (the HUD shows ∞). proj: 'pulse' fires a cyan bolt at speed 22. The fire sound is the synthesized play('pulse') sting (square 220→55 Hz plus saw 880→140 Hz). To put a GLB on this slot later, add a weapon_1 row to ASSET_PACK and the loader will replace the procedural mesh. To retune the feel, change the numbers on that WEAPON_DEFS row (keep MAG_SIZE[1] at 0 while ammo is infinite).

Aim assist, look sensitivity, and movement knobs are in Lesson 10.

6. Registering a new enemy, weapon, or prop

There is no registerEnemy() API. The editor Things tab is built from the real tables:

  • Enemies: add a key to ENEMY_DEFS. The Things tab lists Object.keys(RT.ENEMY_DEFS). buildEnemyMesh already has shapes for drone, titan, turret; anything else uses the soldier / heavy body. Add ASSET_PACK.enemy_yourkey if you have a GLB. You may also add a row to MODEL_SLOTS if you want it in the Custom 3D models UI.
  • Props: add a key to PROP_DEFS. buildPropMesh has a switch of named cases and a default crate-like box. Optional: ASSET_PACK is not used for every prop; custom props use the prop_<key> slot on the project (attachModel(mesh, 'prop_' + e.s, ...)).
  • Weapons: WEAPON_DEFS ships with six entries, and the default HUD / number keys are built around those six. MAG_SIZE and RELOAD_TIME are parallel arrays. Pickup items such as w_shotgun give a weapon index (give: { weapon: 2, shells: 8 }). A third-party page can call registerWeapon(def) on the DMB Tech 1 engine (before loadMap) to append a slot. The safe first step inside the editor is still to retune an existing slot.

Unknown enemy types in a map file fall back to grunt (e.s in ENEMY_DEFS ? e.s : 'grunt').

Sound effects are not files

Gunshots, doors, pickups, and so on are synthesized with the Web Audio API inside the Sound object in dmbtech1.js. There is no assets/sfx/ folder. api.sound(name) in a level script (Lesson 13) can play those named effects: pistol, pulse, rifle, shotgun, rocket, plasma, wrench, hit, explode, bolt, alert, pain, edie, hurt, pickup, weapon, key, door, locked, empty, step, reload, reload2, jump, win, ui.

Lesson 6 — Make an escape-pad map

Lesson 6 of 15 · 10 min

Time: about 10 minutes

Payoff: a tiny level you can walk, with a start and an exit pad that ends the level.

An escape-pad map is a level whose goal is to reach an Exit pad. Standing on the pad (distance under 0.42 cells) calls levelComplete(). Every trial pack map works this way.

Start a clean level

  1. Menu → Projects → New project (save the current one first if you care about it).
  2. You get one empty level named Level 1. Open the Level tab and name it something like Pad Drill.
  3. Optional: set a sky (Night City, Red Dusk, Overcast, Toxic Haze, Black Void), a music track, and a par time.

Default new-level size is 40×32 cells. You can resize in the Project / Level size controls. The engine accepts 8 to 128 on each side (normalizeLevel).

1. Name the file carefully

The loader only accepts a tight path. This is the real check in app.js:

javascript
// Official trial maps: #pack=maps/name.retro (same origin only).
// Also allowed: packs/name.retro. Letters, numbers, dot, underscore, hyphen.
const PACK_PATH = /^(?:maps|packs)\/[A-Za-z0-9][A-Za-z0-9._-]*\.retro$/;

Lesson 12 of 15 · 5 min

Time: about 5 minutes

Payoff: a short list you can actually use when something is blank, silent, or missing.

Black screen, or "needs Three.js"

The 3D library (three.js r128) loads from a CDN on first launch. Go online once, then reload. If you are in an in-app browser (TikTok, Instagram, Facebook), open the link in Chrome, Samsung Internet, Firefox, or Safari instead.

"3D NOT AVAILABLE" / WebGL

Playtest shows a panel: this browser could not start WebGL. The editor still works. Try a full browser (not an in-app one), turn off battery saver or "lite" mode, and enable hardware acceleration. Update the browser if it is very old.

Enemies look like simple robots, music is synth

The asset pack did not load. That is normal when the page is opened as file:// with no internet. Preview through Spck/Acode, or use the hosted app. Check the console for RetroEngine: model failed to load.

A new GLB never appears

  • Path typo in ASSET_PACK (in dmbtech1.js) (it is relative, like assets/models/name.glb).
  • You edited app.js but are playing retroengine.html without running build.py.
  • The hosted assetBase does not have the new file yet (you changed source but did not publish assets/).
  • The file is huge or not a real .glb. Lights in the file are stripped; they will not "light up" the level.

A custom upload vanished, or "storage is full"

Browser storage is about 5–10 MB per site. Uploaded models fill it quickly. Export a .retroengine.json or .retro, remove unused models (Project → Custom 3D models → ✕ or All built-in), and import again.

Share link does nothing

Some in-app browsers block the share sheet and the clipboard. Select the URL in the box and copy it, or export a .retro. Remember the ~7 KB (LINK_MAX 7500) cap, and that file:// links only work on that device.

#pack= says the link is not valid, or the map does not load

The path must match maps/name.retro or packs/name.retro with a simple file name. It must be on the same origin as the app. A typo, a missing file on Pages, or a cross-site URL will toast an error.

Mouse look will not lock

Some browsers block pointer lock. Drag to look instead. On a phone, drag the right half of the screen (or drag on FIRE to aim).

Slow on a phone

Leave Graphics quality on Auto, or pick Low in Settings. Close other apps. Turn off battery saver (it caps frame rate). The known limit is that very old phones may stay under 60 fps even on Low.

Playtest will not start

Menu → Check level. If the start is inside a wall or door, that is an error and Play is blocked. Other issues (no exit, unreachable pad, entity in a wall) are listed as warnings or errors.

A level script does nothing

Imported file and share-link scripts are moved to scriptPending and cleared from script until you review and Apply them (Lesson 13). Pack scripts stay on. A syntax error toasts Script syntax error on Apply, or Script error: ... at run time.

Sound is silent

Phones require a tap before audio. Tap the splash (TAP TO BOOT), and tap once in the game if you skipped that. Check Master / Effects / Music sliders in Settings.

Autosave looks gone

You may be in a different browser, private mode, or the site data was cleared. This is why Lesson 8 tells you to export .json / .retro files.

ADVANCEDLesson 13 — Level scripts

Lesson 13 of 15 · 10 min

Time: about 10 minutes

Payoff: a message when the level starts, and a heal plus a line of text when the Titan dies — the same pattern the trial maps use.

RetroEngine already has a real level-script system. You do not need a new .js module or a hook into the engine game loop for map logic. Each level stores a JavaScript string in level.props.script. When the level starts, DMB Tech 1 runs it once and lets it subscribe to events.

Compare

this is like a TI-89 program that sits in a loop and waits for keys, except you register a small function for each event. In VB, it is closer to WithEvents than to a big Do loop.

Where to type the script

Either:

  • Level tab → Logic → Edit level script, or
  • Menu → Code editor → the script.js tab.

Paste or write the script, then press Apply. Apply first compiles it with new Function('api', text). If the syntax is bad, you get Script syntax error: ... and nothing is saved. If it is fine, the text is stored on the level, any scriptPending flag is cleared, and a toast says to Playtest.

The starter example already in the editor (SCRIPT_EXAMPLE) is:

javascript
// Level script — runs when the level starts.
// Events: 'start', 'tick'(dt), 'kill'(enemyType), 'pickup'(itemType),
//         'door'({x,y}), 'use'({x,y}), 'exit'
// api: message, heal, giveArmor, giveAmmo, openDoor, enemiesLeft,
//      kills, time, win, sound, player
api.on('start', () => api.message('Find the exit. Stay alive.'));
api.on('kill', () => {
  if (api.enemiesLeft() === 0) api.message('Sector clear!');
});

The real api object

This is the object the engine actually builds in runScript() and passes in as api:

CallWhat it does
api.on(event, fn)Register a function for an event. You can call this more than once.
api.message(text)Show a line on screen (up to four at a time; they wait if a menu is open).
api.heal(n)Add n to health, clamped 0–200.
api.giveArmor(n)Add n to armor, clamped 0–200.
api.giveAmmo(type, n)Add ammo. type must already be a key of AMMO_MAX: bullets, shells, cells, or rockets.
api.openDoor(x, y)Open the door in cell (x, y) even without a key (force).

api.time()Seconds since the level started.
api.win()Finish the level (same as stepping on an exit pad).

Pack scripts stay on; shared scripts are reviewed

This is a safety rule in importMapObject:

  • Official same-origin #pack=maps/name.retro loads with how === 'pack'. The script stays on and Playtest starts.
  • A share link (#map=) or a dropped / imported .retro moves a non-empty script into props.scriptPending and clears props.script. The Level tab shows that it is switched off. You read it, then Apply to turn it on.

Treat other people's scripts like a program you did not write: read every line before Apply. A script can call api.win(), change ammo, and (because it is ordinary page JavaScript) also call browser APIs. That is why the switch-off exists.

If you ever need a separate JS file

Maps should keep using props.script. A new engine-wide module would mean adding a <script src="my-module.js"></script> next to app.js in index.html, and teaching build.py to include it in retroengine.html. There is no plug-in hook for that today. Prefer a level script, or a careful change inside DFRuntime, over inventing a side file.

ADVANCEDLesson 14 — Calling APIs from a script

Lesson 14 of 15 · 10 min

Time: about 10 minutes

Payoff: a level that, on start, shows a real temperature from a free public weather API, with errors handled so a dead network does not break the map.

api has no fetch method. A level script is still ordinary JavaScript running in the page (new Function('api', src)(api)), so the browser's built-in fetch is visible as a global, the same way Math is. Use it only for public data, and only when the player has a network connection.

Compare

await fetch(...) is like a TI-89 program that Pauses until another calc answers a GetCalc, or like VB XMLHttpRequest / Await a network call. The game keeps drawing while the reply is in flight, because we do not freeze the whole engine — we only wait inside our little async function.

async / await in one breath

  • fetch(url) returns a Promise: a value that will show up later.
  • await means "pause this function until that Promise finishes."
  • The function that uses await must be marked async.
  • api.on('start', () => { ... }) is not async by itself, so we start an inner async function and run it. The start event can return immediately; the message appears when the reply lands.

CORS, in plain terms

Browsers block a page from reading another site's data unless that site says it is allowed. That rule is CORS. If the API does not send the right headers, fetch fails in the console even though the URL works in a new tab. The example below uses Open-Meteo, a free forecast API that allows browser calls and needs no key.

If a fetch fails with a CORS error, you cannot "fix" it from the level script. Pick an API that allows browsers, or have your own server talk to the other site. Do not look for a secret header hack in client code.

Never put secret keys in game code

Anything in a level script, in app.js, or in a shipped .html file is public. Anyone can Save-As or open DevTools and read it.

  • No API tokens, no passwords, no webhook secrets, no private X / Discord / database keys.
  • If a service requires a key, it does not belong in RetroEngine client code.
  • A #pack= map is especially public: the .retro file is just JSON, and the script is sitting in level.props.script in plain text.

This is also why imported scripts stay off until you review them (Lesson 13). A hostile script could call fetch too.

A paste-ready example

This asks Open-Meteo for the current temperature near Chicago (change the numbers if you want a different city). Paste it into script.js, Apply, then Play while online. Hosted RetroEngine or a Spck preview both work; file:// often cannot fetch other sites.

javascript
// When the level starts, show a line, then ask a public weather API for the temperature.
api.on('start', () => {
  // Instant payoff so the player is not staring at a silent map while the net works.
  api.message('Checking outside conditions…');

  // Inner async function so we can use await. The () at the end starts it immediately.
  (async () => {
    try {
      // Open-Meteo: no key, CORS-friendly. latitude/longitude are Chicago.
      // current=temperature_2m asks for just the current temperature.
      const url = 'https://api.open-meteo.com/v1/forecast?latitude=41.85&longitude=-87.65&current=temperature_2m&temperature_unit=fahrenheit';

      // fetch() is the browser's HTTP call. await waits for the headers/status.
      const res = await fetch(url);

      // res.ok is false for 404, 500, and other HTTP errors. Throw so catch can talk.
      if (!res.ok) throw new Error('HTTP ' + res.status);

      // Parse the JSON body. await again: the body streams in after the headers.
      const data = await res.json();

      // Defensive read: APIs change, so we never assume the shape blindly.
      const t = data && data.current && data.current.temperature_2m;

      if (typeof t === 'number') {
        // Math.round keeps the HUD line short. This is a message, not a game rule.
        api.message('Outside temp near Chicago: ' + Math.round(t) + ' F');
      } else {
        api.message('Weather data was incomplete.');
      }
    } catch (err) {
      // Offline, CORS, typo, or a dead API should never freeze or crash the level.
      api.message('Could not reach weather net.');
      // console.warn is for you in DevTools; players do not see it.
      console.warn('RetroEngine weather fetch', err);
    }
  })();
});

You can keep your Titan / key messages in the same script; just add more api.on(...) blocks.

What "good" looks like

  • A visible fallback message when the call fails.
  • No key or cookie in the URL or in the script.
  • No await fetch on every tick (that would hammer the API and stutter a phone). Once on start, or once on use of a terminal prop, is enough.
  • The map still plays if the request never returns.

Lesson 15 — Stairs, catwalks and jumping

Lesson 15 of 15 · 10 min

Time: about 10 minutes

Payoff: a watchtower you can walk up, plus a jump you can feel, using the real height tools.

DMB Tech 1 already has floor heights. You do not need a new engine feature to build stairs, a catwalk, or a prison-yard wall. This lesson shows where the knobs are, then you stamp a tower and play it.

Floor heights

Every cell has a number in fh (floor height), in world units. The ground is 0. The engine stores the grid in row-major order, so the index of cell (x, y) is y * width + x.

HeightWhat it is forCan you walk up to it?
0Ground—
0.15One stair step, or a curbYes
0.30Second stepYes, from 0.15 or from 0 (0.30 is under the max climb)
0.45Third stepYes, from 0.30 (not in one step from 0)
0.60Catwalk / tower deckYes, from 0.45 or 0.30
0.75Cover block (sandbags-high)No. This is waist-high cover.

The max you can walk up in one step is STEP_H in dmbtech1.js, which is 0.36. Two 0.15 steps are fine. A jump of more than 0.36 is a ledge: the flood-fill in Menu → Check level will say the exit cannot be reached if you skipped a stair.

Jumping does not replace stairs. Space (or the JUMP button) sets G.vz = 3.6. Against gravity 11, that peaks a little under 0.60, so you still want stairs to get onto a catwalk. You cannot jump onto a 0.75 cover block from the ground.

Height tool and Floor height buttons

  1. Select Height (key U) in the tool bar. The hint reads: "Raise floors: 0.15 steps = stairs, 0.6 = catwalk, 0.75 = cover block (can't climb)."
  2. Open the Build tab. Under Floor height are the buttons 0, .15, .30, .45, .60, and Block (0.75). They set ED.brush.fh.
  3. Paint on floor cells (not walls). The 2D map tints raised cells blue, or orange when the height is above STEP_H * 2.
  4. Turn Floor heights on in Project → Map layers if you want to see the tint.

The Floor tool (F) paints a texture and carves through walls. Height never places a wall. If you need a texture and a height (a curb, a grate catwalk), paint the floor first, then paint the height on top.

Editing fh in code

You can set heights in a .retro file, in the code editor (Menu → Code editor → level.json), or in a small script you are writing for yourself. This is the real layout:

javascript
// Floor height is one number per cell, row-major.
// Index of cell (x, y) is y * width + x. Width is level.w.
const x = 10;                 // cell column
const y = 4;                  // cell row
const i = y * level.w + x;    // 4 * width + 10

level.fh[i] = 0.15;           // one stair step (or a curb)
// level.fh[i] = 0.30;        // second step
// level.fh[i] = 0.45;        // third step
// level.fh[i] = 0.6;         // catwalk — only walk onto this from 0.30 or 0.45
// level.fh[i] = 0.75;        // cover block; the player cannot climb it

A short stair run in a loop:

javascript
// Build a 4-step stair going +y, two cells wide, starting at (x, y).
// 0.15, 0.30, 0.45, then 0.60 (the catwalk landing).
const steps = [0.15, 0.30, 0.45, 0.60];
for (let s = 0; s < steps.length; s++) {
  for (let t = 0; t < 2; t++) {          // width of 2
    const i = (y + s) * level.w + (x + t);
    level.fh[i] = steps[s];
  }
}
