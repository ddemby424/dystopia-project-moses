Work on DYSTOPIA in VS Code

Tiny steps. Each one takes 1 to 5 minutes and ends with something you can see. Do one, take the win, then do the next. Stuck? Skip it and come back.

📱 On the Android tablet? Tablet version (Spck / Acode)

Jump: Get code · Open · Folders · Run · Change stuff · Assets · Push · Test · 3D tutorial

0. Words you'll see (1-minute read)

  • Repo = the project folder that lives on GitHub. Like a TI-89 program group, but online.
  • Clone = copy the repo onto your PC, with its history.
  • Commit = a save point with a note. Like "Save As v2" but it remembers every version.
  • Push = send your commits up to GitHub. GitHub Pages then updates the live game in about 1 minute.
  • Extension = an add-on for VS Code, like a VB add-in.

Part 1: Get the code

1. Install the 3 tools

Install these (all free, click Next until done): VS Code, Git, Node.js (LTS).

👀 Win: VS Code opens and shows a Welcome tab.

2a. Get the code with git clone (best)

In VS Code press Ctrl+Shift+P, type Git: Clone, press Enter, paste:

https://github.com/ddemby424/dystopia-project-moses.git

Pick a folder like Documents. Click Open when it asks.

👀 Win: the left sidebar fills with files like index.html and game.js.

2b. Or download the ZIP (no git)

Open the repo on GitHub, click the green Code button, then Download ZIP. Right-click the ZIP, Extract All.

⚠️ A ZIP can't push back to GitHub. Fine for poking around. Use 2a when you want to publish changes.

👀 Win: a folder called dystopia-project-moses-main.

Part 2: Open it

3. Open the folder (not one file)

VS Code menu: File → Open Folder… and pick the repo folder. If it asks "Do you trust the authors?", click Yes.

Always open the whole folder. Opening only game.js hides everything else.

👀 Win: click game.js in the sidebar and the code shows in colour.

Part 3: What's in the box

4. The folder map

dystopia-project-moses/
├─ index.html          the page skeleton: menus, HUD, buttons. Loads the two files below.
├─ style.css           all the looks: colours, fonts, sizes, menu layout.
├─ game.js             ALL the game code (~530 KB). Levels, weapons, Sentinels, sound.
├─ models/            3D models (.glb). Sentinels, guns, props.
├─ images/            pictures. images/tex/ = wall and floor textures.
├─ audio/             short sounds and voice lines (.mp3), e.g. colossus_loved.mp3
├─ music/             background songs (.mp3)
├─ media/             the trailer video + poster + its sources list
├─ fonts/             the game's fonts (.woff2) and their licences
├─ icons/             app icons for phones
├─ tools/             test robots: regression.js (big test), shots.js (screenshots)
├─ learn-3d-…/        these tutorials
├─ manifest.webmanifest  lets phones "install" the game
├─ CREDITS.md         who made which asset, and its licence
├─ STORY_BIBLE.md     the lore
└─ README.md          project notes

Think of it like a VB project: index.html = the Form, style.css = the Properties window, game.js = the code module.

🧪 Try: open index.html and scroll to the bottom. You'll see the line that loads game.js.

Part 4: Run it on your PC

5. Why double-clicking fails

Double-click index.html and the page opens as file://…. Browsers block a file page from loading other files, so the models and textures won't load (grey boxes, stuck loading bar). You need a tiny local web server.

6. Install Live Server

Click the Extensions icon (4 squares) on the left, or Ctrl+Shift+X. Search Live Server (by Ritwick Dey). Click Install.

👀 Win: a Go Live button appears at the bottom-right of VS Code.

7. Play it locally

Click Go Live. A browser opens at something like http://127.0.0.1:5500/index.html.

👀 Win: DYSTOPIA loads, with models, on your own PC.

🧪 Try: in style.css change any colour, press Ctrl+S. The browser refreshes by itself.

Part 5: Change common things

8. Find anything with Ctrl+F

Open game.js, press Ctrl+F, type a word below. Enter jumps to the next hit. Ctrl+Shift+F searches every file.

walkSpeed: 14          player run speed (try 20)
jumpVel: 8.5           jump height
weapons: [             all guns: damage, ammo, fireRate, spread
damage: 28             Pulse Cannon damage
const jobs = [         the list of every 3D model the game loads
const PROP_BUILDERS    how each prop (powerbox, airduct…) is built
function genFloorLayout   where props get placed in each level
CREDITS_HTML           the in-game credits screen
function playTrailer   the startup trailer

Also handy: Ctrl+G = go to line number. Ctrl+Z = undo. Alt+Z = wrap long lines.

👀 Win: change walkSpeed: 14 to walkSpeed: 24, save, play. You zoom.

🧪 Then put it back to 14 (or keep it, your game!).

Part 6: Assets (models, pictures, sounds)

9. Where each kind lives

3D models (.glb)        models/          e.g. models/ph_power_box.glb
Textures (.jpg)         images/tex/      e.g. images/tex/metal_wall_1k.jpg
Sounds, voices (.mp3)   audio/           e.g. audio/colossus_loved.mp3
Music (.mp3)            music/
Video (.mp4)            media/           media/dystopia_trailer_720p.mp4
Fonts (.woff2)          fonts/           + the licence .txt next to it

10. Naming rules

  • all lowercase, words joined with _: crate_metal.glb ✅ Crate Metal(1).GLB ❌
  • no spaces (the live site is picky about case: Crate.glb ≠ crate.glb)
  • textures end in their size: _1k.jpg
  • prefix by source if you like: ph_ = Poly Haven, pp_ = Poly Pizza

11. Phone budget (so it stays smooth)

One prop          under 5,000 triangles,  under 500 KB
One enemy model   under 20,000 triangles, under 2 MB
Textures          1024×1024 (1K) max, .jpg (or .png only if it needs see-through)
Sounds            .mp3, under 200 KB each
Music             .mp3, 128 kbps

Check a model: drag it onto gltf-viewer.donmccurdy.com. It shows size and triangles.

12. Shrink a big model (1 command)

Open VS Code's terminal: Ctrl+` (the key under Esc). Paste:

npx @gltf-transform/cli optimize models/big.glb models/crate_metal.glb --texture-compress webp --texture-size 1024 --simplify-ratio 0.25

0.25 keeps a quarter of the triangles. Too blobby? Try 0.5.

👀 Win: the new file is much smaller. Check it in the viewer from step 11.

13. Worked example: add a new 3D prop

13a. Drop the file in. Download a model (e.g. a crate from Poly Pizza, or one you made on Meshy). Rename it crate_metal.glb, put it in models/.

13b. Add it to the loader list. In game.js, Ctrl+F → const jobs = [. Find the ph_airduct line and add ONE line under it:

    { file: 'models/ph_airduct.glb', role: 'prop:ph_airduct', height: 0.75 },
    { file: 'models/crate_metal.glb', role: 'prop:crate_metal', height: 1.0 },

height = how tall it ends up in metres (the game auto-scales it). The part after prop: is its nickname.

13c. Teach the game how to build it. Ctrl+F → const PROP_BUILDERS = {. Paste this right after that line:

  crate(o) {
    const g = new THREE.Group();
    const c = cloneProp('crate_metal');               // the nickname from 13b
    if (c) {
      c.position.set(0, 0, 0);                        // nudge: x, up, z (metres)
      c.scale.setScalar(o.scale || 1);                // bigger: { scale: 1.5 }
      g.add(c);
    }
    return { g, collide: null };
  },

13d. Place it in a level. Ctrl+F → add('powerbox', 3.95, 60.5. On a new line under it paste:

    add('crate', 3.0, 58.0, { rot: Math.PI / 4, scale: 1.2 });

3.0, 58.0 = x and z on the floor map. rot = turn in radians (Math.PI / 2 = 90°, Math.PI = 180°), just like TI-89 radian mode.

👀 Win: save, the Live Server page reloads, walk to that spot: your crate is there.

🧪 Try: change rot to Math.PI and scale to 2.

14. Add a sound

Put alarm_beep.mp3 in audio/. Anywhere you want it to play (e.g. inside a function that runs on an event), paste:

try { if (!SFX.muted) { const a = new Audio('audio/alarm_beep.mp3'); a.volume = 0.8; a.play().catch(() => {}); } } catch (e) {}

This is the same pattern the game uses for audio/sentinel_dispatch.mp3 (search it to see).

👀 Win: you hear it when that event happens.

15. Swap a texture

Make your picture 1024×1024, save as images/tex/rust_wall_1k.jpg. In game.js Ctrl+F → metal_wall_1k.jpg and change just the filename:

swap(WALL_PBR.map, 'images/tex/rust_wall_1k.jpg', '#4a5670', true, 3);

👀 Win: every wall now wears your texture.

16. Credit it (every time)

Open CREDITS.md and add one line, e.g.:

- "Metal Crate" by SomeArtist via Poly Pizza, CC BY 3.0 — models/crate_metal.glb

CC0 = no credit needed (still nice). CC BY = you must credit: also add it to the in-game screen (Ctrl+F → CREDITS_HTML). "NC" or "ND" licences: skip that asset.

17. Test, then publish

Play it with Go Live (step 7). Looks good? Push it (Part 7).

Part 7: Save, commit, push

18. Save

Ctrl+S. A white dot on a tab = not saved yet. Tip: File → Auto Save turns that worry off.

19. Commit

Click Source Control on the left (the branch icon, Ctrl+Shift+G). Your changed files are listed; click one to see red (old) vs green (new). Type a note in the box, like Faster walk speed, click ✓ Commit. If it asks to stage all changes, click Yes.

First time only, git asks who you are. In the terminal (Ctrl+`):

git config --global user.name "ddemby424"
git config --global user.email "ddemby424@users.noreply.github.com"

20. Push

Click Sync Changes (or ⋯ → Push). First time, it opens GitHub in the browser to sign in; click Authorize.

👀 Win: wait about 1 minute, open the live game, hard-refresh (Ctrl+Shift+R). Your change is live for everyone.

Part 8: Run the test robot

21. One-time setup

Terminal (Ctrl+`) in the repo folder:

npm install playwright-core
npx playwright install chromium

22. Run the big test

node tools/regression.js --quick

That's the fast version (2 floors). The full one, all 9 levels plus phones, takes a while:

node tools/regression.js

If Chrome isn't found, add its path, e.g. --chrome "C:\Program Files\Google\Chrome\Application\chrome.exe".

👀 Win: lines saying PASS scroll by, then a total like 264/264. Any FAIL line tells you which level and what broke. Screenshots go to regression-out/.

You did it

Get code → open folder → Go Live → change one thing → commit → push. That loop is the whole job. Everything else is just more loops.
