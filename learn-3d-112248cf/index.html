Learn 3D games in 10 tiny steps

Two brick rooms, a hallway, and your own first-person hand. Each step takes about 5 minutes and you can play the result straight away. Lost? Open the step's .html file, it has the full code.

How to work: make a folder, put step1.html and an assets/bricks.jpg in it, edit in VS Code, and run python3 -m http.server, then open localhost:8000/step1.html. (Textures don't load from file://.) Lines go in the order you see them in the full file, and the "game loop" lines go inside loop().

0. What's a library and an API? (2-minute read)

Library = someone else's prewritten functions. On your TI-89 you never wrote sin() or Line, because they were built in. three.js is a big pack of built-in commands for 3D that we borrow.

CDN = a website that hosts the library. This one line loads it, like installing a program onto the calculator:

<script src="https://cdn.jsdelivr.net/npm/three@0.128.0/build/three.min.js"></script>

API = the list of commands a library offers, plus how to call them. Every three.js command starts with THREE., the way TI-89 commands live in its catalog menu.

Objects bundle data and actions together, just like VB controls. Properties are values: Text1.Text = "hi" in VB is cube.position.y = 2 here. Methods are actions: List1.AddItem "x" in VB is scene.add(cube) here.

new creates a fresh object from a blueprint, like dragging a new TextBox onto a VB form. const cam = new THREE.PerspectiveCamera(...) means "make a camera and call it cam".

That's it. You already know variables and functions. A library just hands you lots of ready-made ones. Look for the 📚 notes in each step.

1. Scene, camera, renderer

A scene is the box of stuff, the camera is your eye, the renderer paints what the eye sees onto a <canvas>. Three objects, every 3D game ever.

Type this:
camera.position.set(0, 1.6, 5);
const Mat = THREE.MeshBasicMaterial;     // "unlit" paint: ignores lights
const cube = new THREE.Mesh(new THREE.BoxGeometry(1, 1, 1), new Mat({ color: 0xff6600 }));
cube.position.y = 1.6;
scene.add(cube);
renderer.render(scene, camera);   // draw ONE picture
📚 Library call:
  • new THREE.Scene() creates an empty world object.
  • new THREE.PerspectiveCamera(70, aspect, 0.1, 100) creates a camera: zoom angle, screen shape, nearest and farthest distance it sees.
  • new THREE.WebGLRenderer() creates the painter. renderer.render(scene, camera) is its method that draws one picture.
  • new THREE.Mesh(new THREE.BoxGeometry(1,1,1), material) creates a 1×1×1 box, and scene.add(cube) puts it in the world.

👀 You should see: An orange square in the middle of a dark screen (it's a cube seen face-on).

🧪 Try changing: Change cube.position.y = 1.6 to 2.5 - where did it go?

2. The game loop

Games redraw ~60 times a second. Each frame: measure dt (time since last frame), update things, draw. Multiply speeds by dt so it runs the same on a slow phone and a fast PC.

Delete these (they did their job):
renderer.render(scene, camera);   // draw ONE picture
Add this:
// ===== STEP 2: the game loop - runs ~60 times a second =====
const clock = new THREE.Clock();
function loop() {
  requestAnimationFrame(loop);
  const dt = Math.min(clock.getDelta(), 0.05);   // seconds since last frame
  cube.rotation.y += 1.0 * dt;                    // 1 radian per SECOND, on any device
  cube.rotation.x += 0.5 * dt;
  renderer.render(scene, camera);
}
loop();
📚 Library call:
  • requestAnimationFrame(loop) is the browser's API: "call loop again before the next screen refresh".
  • new THREE.Clock() creates a stopwatch, and clock.getDelta() returns the seconds since it was last asked.

👀 You should see: The cube spins smoothly.

🧪 Try changing: Change 1.0 * dt to 5.0 * dt.

3. Meshes & materials

A mesh = geometry (the shape) + material (the paint). Same recipe for floors, walls, enemies, guns.

Add this:
// ===== STEP 3: meshes = geometry (shape) + material (paint) =====
const floor = new THREE.Mesh(new THREE.PlaneGeometry(30, 30), new Mat({ color: 0x555560 }));
floor.rotation.x = -Math.PI / 2;   // planes stand up by default; lay it flat

  • THREE.PlaneGeometry(30, 30) and THREE.SphereGeometry(radius, ...) are more built-in shapes.

4. Textures

A texture is an image glued onto a material via map. RepeatWrapping + repeat tiles it so bricks stay brick-sized.

Add this:
// ===== STEP 4: textures = pictures glued onto materials =====
const loader = new THREE.TextureLoader();
function brick(rx, ry) {
  const t = loader.load('assets/bricks.jpg');
  t.wrapS = t.wrapT = THREE.RepeatWrapping;   // tile it instead of stretching
  t.repeat.set(rx, ry);
  return t;
}
const testWall = new THREE.Mesh(new THREE.BoxGeometry(4, 3, 0.3), new Mat({ map: brick(2, 1.5) }));
testWall.position.set(0, 1.5, -2);
scene.add(testWall);
📚 Library call:
  • new THREE.TextureLoader().load('file.jpg') fetches an image and returns a texture object.
  • THREE.RepeatWrapping is a constant (a named setting), and t.repeat.set(x, y) sets how many times the image tiles.

👀 You should see: A brick wall behind the cube.

🧪 Try changing: Change brick(2, 1.5) to brick(8, 6) - tiny bricks!

Add this:
camera.position.set(0, 22, 10);   // bird's-eye view of the building
camera.lookAt(0, 0, 0);
// ===== STEP 5: a building is just boxes =====
const walls = [];
function wall(x, z, w, d) {          // centre x,z  size w (along x) by d (along z)
  const h = 3;
  const m = new THREE.Mesh(new THREE.BoxGeometry(w, h, d), new Mat({ map: brick(Math.max(w, d) / 2, h / 2) }));
  m.position.set(x, h / 2, z);
  scene.add(m);
  walls.push(m);
}
for (const s of [-1, 1]) {            // s=-1 builds room A (left), s=+1 room B (right)
  const cx = 8 * s;                   // room centre
  wall(cx, -4, 8.3, 0.3);             // north wall
  wall(cx,  4, 8.3, 0.3);             // south wall
  wall(cx + 4 * s, 0, 0.3, 8);        // outer end wall
  wall(4 * s, -2.6, 0.3, 2.8);        // inner wall, split to leave a doorway
  wall(4 * s,  2.6, 0.3, 2.8);
}
wall(0, -1.2, 8, 0.3);                // hallway sides
wall(0,  1.2, 8, 0.3);
📚 Library call:
  • m.position.set(x, y, z) is a method that moves an object in one call.

👀 You should see: A top-down view: two brick rooms joined by a hallway.

🧪 Try changing: Make the hall longer: change both 8s in the hallway walls... and the room centres. Notice what breaks.

6. Moving with WASD + mouse

We keep two angles: yaw (turn) and pitch (look up/down). WASD makes a forward/side amount, and sin/cos of yaw turns that into world X/Z. Click = pointer lock.

Delete these (they did their job):
camera.position.set(0, 22, 10);   // bird's-eye view of the building
camera.lookAt(0, 0, 0);
Add this:
camera.position.set(-8, 1.6, 0);   // stand in room A at eye height
camera.rotation.order = 'YXZ';      // turn left/right first, then look up/down
// ===== STEP 6: keyboard + mouse =====
const keys = {};
addEventListener('keydown', e => keys[e.code] = true);
addEventListener('keyup',   e => keys[e.code] = false);
let yaw = -Math.PI / 2, pitch = 0;   // yaw = turn left/right, pitch = look up/down
const clampPitch = p => Math.max(-1.4, Math.min(1.4, p));
renderer.domElement.addEventListener('click', () => renderer.domElement.requestPointerLock && renderer.domElement.requestPointerLock());
addEventListener('mousemove', e => {
  if (!document.pointerLockElement) return;
  yaw -= e.movementX * 0.002;
  pitch = clampPitch(pitch - e.movementY * 0.002);
});
  let fwd  = (keys.KeyW ? 1 : 0) - (keys.KeyS ? 1 : 0);
  let side = (keys.KeyD ? 1 : 0) - (keys.KeyA ? 1 : 0);
  const speed = 4 * dt;                            // 4 metres per second
  const mx = (-Math.sin(yaw) * fwd + Math.cos(yaw) * side) * speed;
  const mz = (-Math.cos(yaw) * fwd - Math.sin(yaw) * side) * speed;
  camera.position.x += mx; camera.position.z += mz;
  camera.rotation.set(pitch, yaw, 0);
📚 Library call:
  • addEventListener('keydown', fn) is the browser's API: "run fn when a key is pressed", like VB's Form_KeyDown.
  • requestPointerLock() hides the mouse pointer and reports only how far the mouse moved.

👀 You should see: You're standing in room A. Click, then WASD + mouse to walk. (You can walk THROUGH walls - fixed in step 8.)

🧪 Try changing: Change 4 * dt to 10 * dt - sprint mode.

7. Touch controls (iPhone)

Same movement, new inputs: a left-half virtual joystick feeds joy.x/joy.y into the same fwd/side numbers; right-half drag changes yaw/pitch. Input is just numbers.

Add this:
#stick{position:fixed;left:30px;bottom:30px;width:120px;height:120px;border-radius:50%;border:2px solid #fff6;z-index:5;pointer-events:none}
#knob{position:absolute;left:35px;top:35px;width:50px;height:50px;border-radius:50%;background:#fff8}
<div id="stick"><div id="knob"></div></div>
// ===== STEP 7: touch = left-half joystick, right-half drag to look =====
const joy = { x: 0, y: 0 };
let joyId = null, lookId = null, lastX = 0, lastY = 0;
const stick = document.getElementById('stick'), knob = document.getElementById('knob');
function moveJoy(t) {
  const r = stick.getBoundingClientRect();
  let x = (t.clientX - r.left - 60) / 60, y = (t.clientY - r.top - 60) / 60;
  const len = Math.hypot(x, y); if (len > 1) { x /= len; y /= len; }
  joy.x = x; joy.y = y;
  knob.style.left = (35 + x * 35) + 'px'; knob.style.top = (35 + y * 35) + 'px';
}
addEventListener('touchstart', e => {
  for (const t of e.changedTouches) {
    if (t.clientX < innerWidth / 2 && joyId === null) { joyId = t.identifier; moveJoy(t); }
    else if (lookId === null) { lookId = t.identifier; lastX = t.clientX; lastY = t.clientY; }
  }
  e.preventDefault();
}, { passive: false });
addEventListener('touchmove', e => {
  for (const t of e.changedTouches) {
    if (t.identifier === joyId) moveJoy(t);
    else if (t.identifier === lookId) {
      yaw -= (t.clientX - lastX) * 0.005;
      pitch = clampPitch(pitch - (t.clientY - lastY) * 0.005);
      lastX = t.clientX; lastY = t.clientY;
    }
  }
  e.preventDefault();
}, { passive: false });
function endTouch(e) {
  for (const t of e.changedTouches) {
    if (t.identifier === joyId) { joyId = null; joy.x = joy.y = 0; knob.style.left = knob.style.top = '35px'; }
    if (t.identifier === lookId) lookId = null;
  }
}
addEventListener('touchend', endTouch);
addEventListener('touchcancel', endTouch);
  fwd -= joy.y; side += joy.x;
📚 Library call:
  • 'touchstart' and 'touchmove' are the browser's finger events. el.getBoundingClientRect() returns where an element sits on screen.

👀 You should see: On a phone: left thumb walks, right thumb looks. Desktop still works.

🧪 Try changing: Change the look speed 0.005 to 0.01.

8. Collision

Before moving, ask: would my new spot overlap a wall box (grown by my radius)? Test X and Z separately so you slide along walls instead of sticking.

Delete these (they did their job):
  camera.position.x += mx; camera.position.z += mz;
Add this:
// ===== STEP 8: collision = "would my new spot overlap a wall box?" =====
const R = 0.35;                          // player radius
function hits(x, z) {
  for (const w of walls) {
    const p = w.position, g = w.geometry.parameters;
    if (Math.abs(x - p.x) < g.width / 2 + R && Math.abs(z - p.z) < g.depth / 2 + R) return true;
  }
  return false;
}
function tryMove(dx, dz) {               // test X and Z separately = slide along walls
  const p = camera.position;
  if (!hits(p.x + dx, p.z)) p.x += dx;
  if (!hits(p.x, p.z + dz)) p.z += dz;
}
  tryMove(mx, mz);
📚 Library call:
  • w.geometry.parameters reads back the width, height and depth you gave BoxGeometry.

👀 You should see: Walls are solid now; you slide along them and fit through doorways.

🧪 Try changing: Set R = 1.2 - now you're too fat for the hallway.

9. First-person hand in its own pass

The hand lives in a separate scene + camera, drawn AFTER the world with the depth buffer cleared, so it never pokes into walls (exactly DYSTOPIA's gun fix). A little sine wave = walking bob.

Delete these (they did their job):
  renderer.render(scene, camera);
Add this:
  handCam.aspect = innerWidth / innerHeight; handCam.updateProjectionMatrix();
// ===== STEP 9: the hand lives in its OWN scene with its OWN camera =====
const handScene = new THREE.Scene();
const handCam = new THREE.PerspectiveCamera(60, innerWidth / innerHeight, 0.01, 10);
const hand = new THREE.Group();
const skin = new Mat({ color: 0xd9a07a });
hand.add(new THREE.Mesh(new THREE.BoxGeometry(0.09, 0.03, 0.1), skin));           // palm
for (let i = 0; i < 4; i++) {                                                     // fingers
  const f = new THREE.Mesh(new THREE.BoxGeometry(0.018, 0.018, 0.075), skin);
  f.position.set(-0.033 + i * 0.022, 0, -0.085);
  hand.add(f);
}
const thumb = new THREE.Mesh(new THREE.BoxGeometry(0.02, 0.02, 0.06), skin);
thumb.position.set(-0.055, 0, -0.03); thumb.rotation.y = 0.6; hand.add(thumb);
const sleeve = new THREE.Mesh(new THREE.CylinderGeometry(0.04, 0.045, 0.3, 12), new Mat({ color: 0x223344 }));
sleeve.rotation.x = Math.PI / 2; sleeve.position.z = 0.19; hand.add(sleeve);
hand.position.set(0.18, -0.17, -0.35);
hand.rotation.set(0.25, 0.35, 0.15);
handScene.add(hand);
renderer.autoClear = false;              // we clear by hand so two passes can stack
let bobT = 0;
  const moving = Math.abs(fwd) + Math.abs(side) > 0.05;
  if (moving) bobT += dt * 9;
  hand.position.y = -0.17 + Math.abs(Math.sin(bobT)) * 0.012;
  hand.position.x = 0.18 + Math.sin(bobT) * 0.008;
  renderer.clear();
  renderer.render(scene, camera);      // pass 1: the world
  renderer.clearDepth();               // forget wall depths...
  renderer.render(handScene, handCam); // pass 2: hand always on top, never clips
📚 Library call:
  • new THREE.Group() is an invisible container, so moving the group moves every part of the hand.
  • renderer.clearDepth() erases the memory of how far away the walls were, so the hand always draws on top.

👀 You should see: A hand + sleeve bottom-right that bobs as you walk and never clips into walls.

🧪 Try changing: Change bobT += dt * 9 to dt * 20, or move the hand with hand.position.set(...).

10. Lighting

Swap one word: MeshBasicMaterial (unlit) to MeshStandardMaterial (lit). Now lights matter: a dim hemisphere fill plus a coloured point light per room, plus fog.

Delete these (they did their job):
const Mat = THREE.MeshBasicMaterial;     // "unlit" paint: ignores lights
Add this:
const Mat = THREE.MeshStandardMaterial;    // "lit" paint: reacts to lights
// ===== STEP 10: lights (only "Standard" materials care about them) =====
scene.add(new THREE.HemisphereLight(0x8899bb, 0x332211, 0.35));   // soft sky/ground fill
for (const [x, color] of [[-8, 0xffaa55], [0, 0xffffff], [8, 0x55aaff]]) {
  const lamp = new THREE.PointLight(color, 1.6, 14);
  lamp.position.set(x, 2.7, 0);
  scene.add(lamp);
  const bulb = new THREE.Mesh(new THREE.SphereGeometry(0.08), new THREE.MeshBasicMaterial({ color }));
  bulb.position.copy(lamp.position); scene.add(bulb);
}
scene.fog = new THREE.Fog(0x202030, 6, 25);
handScene.add(new THREE.HemisphereLight(0xffeedd, 0x333333, 1.2));
📚 Library call:
  • THREE.MeshStandardMaterial is paint that reacts to light. THREE.HemisphereLight, THREE.PointLight(color, strength, range) and THREE.Fog are built-in light and fog objects.

👀 You should see: Moody rooms: warm orange room A, white hall, blue room B, with light falloff.

🧪 Try changing: Change a lamp colour, e.g. 0xffaa55 to 0xff0000, or the intensity 1.6 to 4.
